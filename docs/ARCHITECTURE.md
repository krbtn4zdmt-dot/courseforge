# Architecture

## High-level flow

```
User chat ──▶ Intake (parse topic + timeframe + prefs)
                 │
                 ▼
          Planner ──▶ topic type, subtopics, time budget
                 │
                 ▼
          Researcher ──▶ search web/YouTube/Wikipedia, score + store sources
                 │
                 ▼
     Curriculum Designer ──▶ syllabus (days → lessons, objectives, minutes)
                 │           [user previews/edits here]
                 ▼
   ┌──── per lesson, just-in-time (Inngest job) ────┐
   │  Lesson Writer ──▶ Examiner ──▶ Fact-Checker   │
   │        ▲                            │          │
   │        └──── rewrite if flagged ────┘          │
   └────────────────────────────────────────────────┘
                 │
                 ▼
            Stored in Postgres ──▶ rendered in UI
```

## Time-budget engine (`src/lib/pipeline/timeBudget.ts`)
Pure function, fully unit-tested.

- `totalMinutes = days × minutesPerDay`
- Default split: lessons 50%, media 20%, practice/quiz 20%, review 10%
- Skill topics: lessons 40%, practice 35%, media 15%, review 10%
- Lessons are 10–25 min each; `lessonsPerDay = clamp(round(minutesPerDay × lessonShare / 15), 1, 4)`
- From day 3 onward, reserve review time for spaced recall of earlier concepts
- Final day: at least 30% of time on review and final quiz

## Generation strategy
- **Syllabus first, fast:** planner + light research + curriculum design, target < 20s.
- **Day 1 immediately** after confirm.
- **Later days ahead of time:** when a user completes day N, queue generation for day N+2. Also a nightly job that generates the next day for active courses.
- Each lesson is generated by its own Inngest step, so one failure doesn't break the course and retries are automatic.

## Research details
- 3–5 search queries per subtopic, generated by the planner.
- Tavily: `search_depth: advanced`, `max_results: 5`, include raw content for top results (for grounding only; never shown verbatim).
- YouTube: search per lesson; filter 3–25 min, English (or user language), sort by relevance; score by views, like ratio, channel subscriber count, recency.
- Wikipedia: summary endpoint for key entities in knowledge topics.
- **Source score** (0–1): domain credibility (allowlist boost for `.edu`, `.gov`, official docs, major encyclopedias/publications; penalty for content farms), relevance (embedding similarity to subtopic), recency (for fast-moving topics only). Keep top 3–6 per lesson.
- Deduplicate by canonical URL and near-duplicate content (embedding similarity > 0.95).

## Data model (Postgres)

```sql
create extension if not exists vector;

create table profiles (
  id uuid primary key references auth.users on delete cascade,
  display_name text,
  created_at timestamptz default now()
);

create table courses (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references profiles(id) on delete cascade,
  topic text not null,
  topic_type text check (topic_type in ('knowledge','skill','hybrid')),
  days int not null check (days between 1 and 60),
  minutes_per_day int not null,
  level text not null,
  goal text not null,
  status text not null default 'draft'
    check (status in ('draft','syllabus_ready','active','completed','failed')),
  plan jsonb,                -- planner output
  created_at timestamptz default now()
);

create table lessons (
  id uuid primary key default gen_random_uuid(),
  course_id uuid references courses(id) on delete cascade,
  day_number int not null,
  position int not null,
  title text not null,
  objectives text[] not null,
  est_minutes int not null,
  status text not null default 'pending'
    check (status in ('pending','generating','ready','failed')),
  content_md text,
  key_terms jsonb,
  practice_task jsonb,
  video_ids text[],
  fact_check jsonb,
  generated_at timestamptz,
  unique (course_id, day_number, position)
);

create table sources (
  id uuid primary key default gen_random_uuid(),
  course_id uuid references courses(id) on delete cascade,
  url text not null,
  title text,
  source_type text check (source_type in ('web','video','wiki','docs')),
  score real,
  excerpt text,              -- short grounding text, never displayed in full
  embedding vector(1024),
  unique (course_id, url)
);

create table lesson_sources (
  lesson_id uuid references lessons(id) on delete cascade,
  source_id uuid references sources(id) on delete cascade,
  primary key (lesson_id, source_id)
);

create table questions (
  id uuid primary key default gen_random_uuid(),
  lesson_id uuid references lessons(id) on delete cascade,
  prompt text not null,
  options jsonb not null,     -- [{id, text}]
  correct_option_id text not null,
  explanation text not null
);

create table progress (
  user_id uuid references profiles(id) on delete cascade,
  lesson_id uuid references lessons(id) on delete cascade,
  completed_at timestamptz,
  quiz_score real,
  feedback text check (feedback in ('too_easy','just_right','too_hard')),
  primary key (user_id, lesson_id)
);

create table llm_calls (
  id bigserial primary key,
  course_id uuid references courses(id) on delete set null,
  agent text not null,
  model text not null,
  input_tokens int,
  output_tokens int,
  cost_usd numeric(10,5),
  created_at timestamptz default now()
);
```

Enable Row Level Security on all user tables: users can only read/write rows tied to their own `user_id` (via `courses.user_id` for child tables). Pipeline jobs use the service role key server-side.

**Embeddings note:** Anthropic doesn't offer an embeddings endpoint. Use Voyage AI (`voyage-3`, 1024 dims) or skip embeddings in MVP and score relevance with a `MODEL_FAST` call. Decide in Phase 1 and record it below.

## Model usage
- `MODEL_SMART` (e.g. `claude-sonnet-5`): planner, curriculum designer, lesson writer
- `MODEL_FAST` (e.g. `claude-haiku-4-5-20251001`): intake parsing, examiner, fact-checker, relevance scoring
- Verify current model names in Anthropic's docs before setting env vars.
